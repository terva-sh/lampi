## Description

Measure costs remaining after bounded streaming. Compare full projection with durable append checkpoints, immutable prior event prefixes and search prefix reuse. Explicitly handle parser state, rewrites/truncations, partial records, sidecars, event IDs/content references and crash recovery before proposing an implementation. Search already skips unchanged SQL writes but still decodes existing events. Produce an implementation decision and narrowly scoped follow-up tickets; do not silently change identity semantics or freshness. Compare debounce changes only as an explicit latency/CPU tradeoff.

## Acceptance criteria

- [ ] Large-session append measurements separate parse, serialize/compress, index, GC and I/O costs.
- [ ] A written checkpoint/prefix reuse design covers rewrite/truncate, state, references, supersession and crash safety, with alternatives and measured tradeoffs.
- [ ] Implementation follow-ups are filed with performance targets and semantic regression cases, or the evidence explains why incremental work is deferred.

## Implementation plan

Measure independent streaming parse-only, parse+indexed-event encoding, and full staged Parquet publication passes, with per-stage CPU, GC pause/allocation and Linux logical/physical I/O counters. Add separately timed real recall index passes to synthetic combined sync/append runs; profiles identify GC/serialization CPU rather than treating cumulative allocation as live memory. Document overlapping component costs and warm-cache limitations. Design authenticated append checkpoints plus immutable event prefixes and search prefix proofs covering full parser state, partial records, rewrites/truncation, sidecars, IDs/references, generation validation and crash recovery. Decide from measurements whether to implement now or file narrow semantic/performance follow-ups; this spike does not authorize changing event identity semantics.
