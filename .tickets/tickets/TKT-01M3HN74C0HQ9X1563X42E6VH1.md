## Description

The root `README.md` is 712 lines and reads as a reference manual. The first
screen explains a name collision. Quickstart is one paragraph about debounce,
backoff, and signals. Registration, many lakes, allowlist semantics, Cursor
internals, redaction, the CLI, build, and git-ticket setup all share one file.
A person who wants to try lampi cannot tell what it is, what it looks like,
or how to start without reading all of it.

### Approach

Make the README a front page for someone who self-hosts a lake: a pitch, a
dashboard screenshot, a Mermaid diagram of the flow, the supported harnesses,
a short quickstart, how to add a machine, and a documentation map. Move each
technical section into a dedicated file under `docs/`. Content moves; nothing
is dropped. Then do a pass over the existing docs for links, stale tables,
and overlap.

### Alternatives considered

- Trim the README in place and keep one file. Rejected: the reference material
  is correct and needed, and a single file cannot serve a first-time reader and
  an operator looking up precedence rules at once.
- A docs site generator (mkdocs, hugo). Rejected: a new build dependency for
  a Go repo whose docs render fine on Forgejo and GitHub as Markdown.
- Screenshot from the live lake. Rejected: it would publish real session
  names and paths. The synthetic fixture in `internal/web/smoketest` shows the
  same UI with made-up data.
- One large PR. Rejected: terva-review fails large PRs on its context limit
  before any model call. The work ships as three stacked Forgejo PRs.

## Acceptance criteria

- [ ] README is a front page: pitch, dashboard screenshot, diagram, harnesses, quickstart, add a machine, docs map
- [ ] Every section of the old README has one destination in docs/, recorded in a note
- [ ] Every relative link and anchor in README.md, docs/, deploy/ and e2e/ resolves
- [ ] Screenshot comes from the synthetic smoketest fixture and contains no real lake data
- [ ] Existing docs: architecture CLI table current, each doc says who it is for, overlap linked not duplicated

## Implementation plan

Three stacked Forgejo PRs.

1. Extract reference: `docs/harnesses.md`, `docs/agent.md`,
   `docs/allowlist-and-redaction.md`, `docs/registration-and-lakes.md`.
   Remove those sections from the README and retarget `deploy/README.md` anchors.
2. Extract the rest and rewrite the front page: `docs/cli.md`,
   `docs/development.md`, `docs/naming.md`, `docs/getting-started.md`,
   `docs/README.md`. New README with Mermaid diagram and docs map.
3. Screenshot from `internal/web/smoketest` via Playwright into
   `docs/images/`, plus a DX pass over existing docs.

Each PR runs a link and anchor checker over README.md, docs/, deploy/ and e2e/.
