## Description

Files over N (e.g. 32 MiB) split into CAS-keyed chunks; manifest lists digests + lengths.

## Implementation plan

Files larger than max_blob_bytes are a logical object, not one CAS blob. The client splits them into chunks of at most that cap (or ChunkBytes when it is smaller), PUTs each chunk, and lists chunk_sha256s plus chunk_lengths on the manifest. sha256 stays the hash of the concatenation. The lake checks those lengths against the stored objects, streams the hash, and records a logical index under cas/logical. It does not install an assembled object past the cap. PUT with a chunk list still refuses a concatenation past the cap, because that call installs one object. A chunk list that fits is still concatenated, as today. A tail is not combined with chunks: a file past the cap is sent whole. Layer B and normalize read the logical concatenation. Tests cover a file past the cap (upload, re-sync, missing chunk, bad hash, bad lengths) and keep the single-object refusal.
