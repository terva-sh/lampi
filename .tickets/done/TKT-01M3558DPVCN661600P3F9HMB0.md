## Description

1) Ingest live terva session → catalog session_uid + sha256
2) Re-sync → zero new blobs
3) Append line → tail only; head sha updates
4) Copy file on machine B → CAS hit; two provenance rows
5) Query normalized text for known prompt

## Acceptance criteria

- [x] Ingest records a session_uid and the blob sha256
- [x] Re-sync uploads zero new blobs
- [x] An appended line uploads the tail only and the head sha updates
- [x] The same file on a second machine is a CAS hit with two provenance rows
- [x] A query finds a known prompt in normalized text
- [x] The five tests run in CI

## Implementation plan

One package, internal/accept, runs the five architecture section 7 checks against a local lake. api.Open sits behind httptest. A fixture terva JSONL is the session. upload.Sync is the client, once per machine.

### Ingest
Machine A syncs the fixture. The catalog session uid is set, and the current artifact sha256 is the file.

### Re-sync
The same sync sends no PUT. The CAS object count stays the same.

### Append
One JSONL line is appended. The only PUT body is that tail. The catalog head sha256 becomes the full file.

### Second machine
Machine B syncs a copy of that file. The digest is already in the CAS, so no blob is stored. Provenance for that digest has one row per machine.

### Query
terva-lampi export writes the normalized JSONL. sqlite json_extract on content_text finds the fixture prompt, the same string the export proof already uses.

CI already runs go test ./..., which includes this package. docs/architecture.md and the README name that package as the MVP gate. The export failure-path test stays in internal/cli; it is not a second copy of the gate.
