## Description

Add explicit opt-in local runtime diagnostics for both long-running processes, shared where practical. Provide heap/allocation, GC and process CPU observations plus deliberate CPU/heap capture. Keep diagnostics off by default and refuse unintended public exposure. Do not log or export tokens, transcripts, auth/session state or arbitrary environment variables. Bound capture duration and shut the listener down cleanly. Add runtime metrics to the existing metrics surface where appropriate, documenting live heap versus process RSS and cgroup page cache. The synthetic harness should validate this without deployment. An unauthenticated public pprof listener is not an acceptable shortcut.

## Acceptance criteria

- [x] Agent and lake support explicit local diagnostic capture with default-off behavior, bounded durations and tested shutdown.
- [x] Runtime memory/GC/CPU measurements are documented and distinguish Go heap, resident memory and reclaimable filesystem cache.
- [x] Exposure and invalid-option tests pass; isolated workload profiles can be captured without reading live credentials or restarting live services.

## Implementation plan

Use a shared file-only diagnostic capture for agent daemon and lake: explicit new private output directory, bounded CPU capture (1s..5m), sampled heap/allocation profile, allowlisted runtime/GC/process CPU/RSS snapshots, default off. This avoids adding any unauthenticated network listener or generic pprof endpoints. Stop capture and flush owned files on service shutdown; reject invalid durations and existing output paths before live config access. Add low-cardinality runtime measurements to the existing lake metrics listener. Validate real captures, default-off, collisions/symlinks, invalid options and early shutdown in isolated tests, then document heap/RSS/cgroup cache distinctions and overhead.
