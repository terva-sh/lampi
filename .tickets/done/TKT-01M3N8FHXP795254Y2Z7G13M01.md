## Description

Lets an operator record that a refused project was reviewed and will not be imported, so it leaves the review queue.

- **Hide** and **Unhide** on `/review` rows, singly or by checkbox selection, with an optional note. The same Hide appears on refused rows of a device's page.
- The operator role is required. The form is CSRF-checked. No recent re-authentication is needed, since hiding adds no access.
- A hide is lake-wide, keyed by git remote or cwd, per the epic's decision. The confirmation says how many devices hold each project.
- A hidden project that a profile later allows drops out of the Hidden tab naturally. A hide never blocks an allow.
- `POST /api/web/v1/review/hide` and `/unhide` take a list of keys and answer with what changed. Documented in `docs/web-api.md`.
- The Hide button says it changes only what the dashboard shows and does not stop the agent. A deny rule on the profile does that.

## Acceptance criteria

- [x] Operators hide and unhide one or many projects with an optional note
- [x] A hidden project leaves Needs review on every device
- [x] The page says a hide does not stop the agent

## Implementation plan

POST /review/{hide,unhide} (form) and /api/web/v1/review/{hide,unhide} (JSON), operator-only and CSRF-checked, calling Catalog.HideProjects and UnhideProjects, then FlushAudit. On the page, checkboxes use the HTML form attribute to join a form outside the table (review-select), so the per-copy Allow forms can stay in the rows without nesting forms. The same selection serves batch Allow next. Each row's Hide is a button bound to a second form (review-hide-one). The device page gets Hide from review or Unhide per refused project, keyed by the template func projectKey (catalog.ProjectKeyOf), and a hidden badge. A successful hide redirects to the validated return with no notice: the row leaving the queue and the Hidden (N) count moving are the feedback, and a query-string notice would repeat the forgeable-notice problem review 1297 found. Rejected: a confirmation page for hides. A hide is reversible and sends nothing to agents.

## Summary

Hide and Unhide on /review, per row or by checkbox selection with an optional note, plus a Hidden tab with per-row and bulk Unhide. A device's page offers Hide from review or Unhide on refused projects and marks hidden ones. The JSON API is POST /api/web/v1/review/{hide,unhide}. Hides are lake-wide, audited as project.hidden and project.unhidden, and the page says a hide does not stop the agent. Tests: TestHideAndUnhideFromTheReviewQueue, TestHideFromTheDevicePage, TestHideAPI. Docs: web-dashboard.md Review and web-api.md Hiding projects.
